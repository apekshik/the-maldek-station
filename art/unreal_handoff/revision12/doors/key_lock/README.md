# Physical key interaction

The seven standard room doors use the rounded brass service key and cylinder from door_study_04. Control-front and both relay entrances retain their digital keypads and code 1234. The brass world-facing interaction prompt and direct inside egress are preserved.

From outside a locked standard door, press E to enter an angled close-up. Hold the left mouse button on the key's rounded head and drag it along its visible path toward the cylinder. Clicking elsewhere, clicking without moving, or moving without holding does not unlock. Releasing holds the partial insertion; grab the key again to resume or pull it back. E, right-click or Escape cancels and restores the player view/input with the lock still secure. Full insertion triggers an automatic turn, return and withdrawal, unlocks, then restores the player view. E opens the door separately. Closing fully re-engages the lock; obstructions still stop door motion safely.

Inside E directly releases and opens the door without a key or code. `bKeyAvailable` starts true on all physical locks; `RequiredKeyId` is the future inventory integration point. No key search is required in this version. Components tear down the interaction safely if the player or door goes away. Door collision and all installed actor transforms are retained; the key housing stays at authored physical scale even on fitted door widths.

The cylinder turn plays the real CC0 recording [Key Twist in lock by KieranKeegan](https://freesound.org/people/KieranKeegan/sounds/418846/), followed by the existing unlock click. `KeyTurnVolume=4` makes the turning recording 3.08 times louder (+9.76 dB) than its initial 1.3 setting without raising other door sounds. Cancellation stops the turning audio. Source, license, original download and reproducible edits are in `art/audio/doors/key_turn`. A small warm inspection light is active only during the key close-up, preserving visibility at dark service doors without changing the player's flashlight state.

**Testing checkpoint:** press **F6** while playing to return to the control-room service door, facing its key lock. This also safely cancels an active keypad/key close-up and skips the opening tutorial for the session. The console command `StationDoorCheckpoint` does the same. The tagged `R12_Door_Test_Checkpoint` marker can be repositioned in the level. This shortcut is available in PIE and non-shipping development builds; the original opening spawn is retained.

Reproduce: run `doors_export_keys.py` in Blender, build game and editor, then run `doors_install_keys.py`, `doors_key_turn_install.py`, `doors_checkpoint_install.py`, `doors_test_keys.py`, `doors_key_edges.py`, `doors_checkpoint_test.py`, and the final key capture/save verification through the exclusive R12 editor dispatcher. The editor-only `SendPIEMousePosition` helper routes pointer motion through the viewport, so automated tests exercise the normal mouse-reading code without moving the desktop cursor.
